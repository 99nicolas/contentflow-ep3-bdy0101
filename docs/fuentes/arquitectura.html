ContentFlow · Arquitectura del flujo de datos (EP3)

Fuente NoSQL → extracción y transformación en Python → carga y visualización en Power BI → reporte automático de KPIs

1 · Fuente NoSQL

MongoDB Atlas · Cluster0 (M0, 3 nodos, São Paulo) · base ContentFlow
usuarios500 docs · genero, dispositivo, fecha_registro
publicaciones500 docs (+3 de prueba) · categoria, tipo, fecha, hashtags[ ]
reacciones499 docs · índice único usuario + publicación
comentarios500 docs · likes
campañas500 docs · publicaciones_asociadas[ ], metricas_objetivo{ }
Conexión: mongodb+srv con TLS · credenciales en .env (no se sube al repo)

2 · Extracción y transformación

Python 3.12 · PyMongo · pandas · scripts/pipeline.py
extraccion.py · 5 agregaciones en el servidor $match (filtro de pruebas y por día) · $lookup + $count · $unwind de arreglos · $unionWith · $group · lectura de campos anidados metricas_objetivo.likes
transformacion.py · 18 transformaciones registradas Estructurales (aplanar, desanidar, agregar) · Semánticas (interacciones, sin_reaccion, segmentos, "Desktop" → "Escritorio") · Formato (fechas, mes, hora, tipos) · Limpieza (pruebas, duplicados, nulos)
kpis.py · 5 KPIs con meta y semáforo K1 sin reacción del día · K2 interacciones/publicación · K3 participación Móvil · K4 cumplimiento de campañas · K5 usuarios activos
Modo --offlineReproduce el mismo resultado desde los JSON del anexo: validó que Atlas y pandas entregan tablas idénticas.
